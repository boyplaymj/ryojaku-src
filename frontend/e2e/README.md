# e2e/ — 發團表單兩步驟精靈的瀏覽器實跑驗收

```bash
cd frontend && npm run e2e
```

## 為什麼有這一支

A3-c 把發團表單改成兩步驟精靈，改動**全部是 UI 行為**。而既有的三道閘對它零鑑別力：

| 閘 | 它證明什麼 | 對「按下去會發生什麼」 |
|---|---|---|
| `npm run typecheck` | 型別接得上 | 看不到 |
| `npm run build` | 打得包起來（esbuild **不驗型別**） | 看不到 |
| `npm test`（`run-tests.mjs`） | 純函式的行為 | 看不到 |

⇒ 這支是**唯一**會去按那顆按鈕的東西。

## rc 的意思（四種，不可互相讀錯）

| rc | 意思 |
|---:|---|
| 0 | 全部通過 |
| 1 | 有測試沒過 |
| 2 | 腳本自己爆了 |
| 3 | **量不到** —— 測試中途頁面被 dev server 重載，紅綠都不可信，請重跑 |
| 4 | **沒有儀器** —— playwright 找不到／dev server 起不來／harness 生不出來 |

🔴 **3 和 4 都不是「失敗」。** 把它們讀成失敗會產生假警報，把它們讀成通過會產生假綠燈。
（rc=3 這一格是真的發生過才加的：2026-09-06 第一次跑時 vite 送了
`✨ optimized dependencies changed. reloading`，元件重新掛載成一張空表單，
於是 T4 出現「按鈕永遠 disabled」這種**看起來很像產品缺陷**的假紅。
現在腳本會先開一頁暖機把 dep optimization 做完，再用 `load` 事件計數當第二道。）

## 七條在驗什麼

| | 斷言 |
|---|---|
| T1 | 未定位 ⇒「下一步」**禁用**，且畫面上只有第一段 |
| T2 | 填入測試資料（寫 `coordinates`）⇒ 按鈕**解禁** |
| T3 | 籌碼 `''` ⇒ **瀏覽器原生 `required`** 擋下（沒有 toast） |
| T4 | 籌碼 `'   '` ⇒ 原生**放行**，改由 `validateCreateGameStage1` 跳 toast |
| T5 | 合格 ⇒ 進第 2 步，第一段卸載、第二段掛上 |
| T6 | 上一步 → 下一步 往返後，第一段欄位、第二段選項、照片**都還在** |
| T7 | 第 2 步送出 ⇒ 服務條款彈窗（API 不會被呼叫） |

🔴 **T3 和 T4 必須成對看。** 原生 `required` 只擋真正的空值，`'   '` 它會放行 ——
只有這一對的**對比**才分得出「原生擋的」與「程式閘擋的」。
T3 自己對「按鈕根本沒作用」零鑑別力（實測見下）。
同理 T1/T2 是同一顆按鈕的反向斷言：少了 T2，T1 對「按鈕永遠 disabled」零鑑別力。

## 一條紅了就停（以及為什麼 rc 要分 1 和 2）

這七條是**一條接一條推進同一個表單狀態**的，所以 `ok()` 一發現紅就中止，剩下的標「未跑」。

理由是實際踩到的：突變 A（拿掉 `stakes` 檢查）會讓畫面在 T4 就跑進第 2 步，
接著 T5 去 `fill` 那個**已經卸載**的籌碼欄位必然拋 locator timeout ——
第一版就這樣把一次**真的抓到回歸**收成 `rc=2 腳本自己爆了`。
現在的歸屬規則：**已經有一條紅了 ⇒ 例外算後果（rc=1）；一條都沒紅卻爆掉 ⇒ 才是設備問題（rc=2）。**

## 這把尺會不會紅？（2026-09-06 四發，全部實跑過）

| 動的東西 | 預期 | 實際 |
|---|---|---|
| 拿掉 `validateCreateGameStage1` 裡的 `stakes` 檢查 | T4 紅 | ✅ T4 紅、rc=1，**且畫面停在「步驟 2 / 2」**（真的漏進去了） |
| 「下一步」`type="submit"` → `type="button"` | T4 紅 | ✅ T4 紅、rc=1，**但畫面停在「步驟 1 / 2」**（按鈕根本沒作用） |
| `HOME` 指到不存在的目錄（找不到 playwright） | rc=4 | ✅ rc=4，訊息講「沒有儀器不是量到失敗」 |
| 拿掉 `index.html` 的 `src="/index.tsx"` 錨點 | rc=4 | ✅ rc=4，拒絕生成 harness |

🔴 **前兩發都是 T4 紅，分辨它們要看「步驟」那個數字**：A 是「漏過去了」，B 是「整顆按鈕死了」。
只看紅綠的話這兩種相反的病長得一樣。
🔴 **突變 B 之下 T3 仍然是綠的** —— 「原生擋住了」與「按鈕沒作用」在 T3 眼裡逐字相同。
這就是上一節「T3/T4 必須成對看」的實證來源。

改動這七條之後**請重跑上面四發**，否則「全綠」與「尺壞了」在結果上長得一樣。

## 刻意不接進 `npm test`

`run-tests.mjs` 是純函式的閘，跑得起來只需要 node。這支要一個瀏覽器＋一個 dev server，
接進去會讓「單元測試紅了」與「這台機器沒裝 chromium」變成同一個訊號。
⇒ 它是**手動的驗收**，不是 CI 閘。改到發團表單時自己記得跑。

## 涵蓋範圍的界線（引用這份綠燈時要一起講）

- 只掛 `pages/CreateGroup.tsx` 這**一個元件**（`e2e/createGroupWizard.harness.tsx`）。
  `App.tsx` 有 `if (!user) return <Login/>` 這道閘，繞過它才驗得到本來要驗的東西。
- ⇒ **證明不了** `/create` 這條路由還通，也證明不了登入閘。
- `user` 是假的、`onCreate` 直接回成功 ⇒ **送出之後的流程完全不在涵蓋範圍內**
  （個資檢查、`api.getUserInfo`、扣 120 點、推播引導、跳轉）。
- T6 的照片**一定會上傳失敗**（本機沒有後端，這是刻意的）。它驗的是
  `imageItems` 這筆活過了 Stage2 的卸載與重掛，不是上傳成功。

## 兩道獨立的「不准碰正式後端」

1. `run.sh` 把 `VITE_API_BASE_URL` 指到本機死路。
   （`services/apiService.ts` 是 fail-closed：沒設就整個 app 起不來，所以**不能不設**。）
2. Playwright 端把所有非本機請求 `abort`，並把攔到的 URL 印出來 —— 印出來是空的才算數。

## 產物

- `e2e/_generated.harness.html`：**執行時從 `index.html` 現生**，跑完刪掉，不進版控。
  刻意不存靜態副本：`index.html` 一改（CDN、全域樣式、入口）它就會靜靜過期，
  而過期的 harness 跟正常的 harness 在畫面上長得一模一樣。
- 截圖 6 張：預設在 `$TMPDIR/a3c-shots/`（⚠️ 本機 `/tmp` 是 tmpfs，重開機就沒了）。
  要留就設 `E2E_SHOT_DIR=/some/dir npm run e2e`。
